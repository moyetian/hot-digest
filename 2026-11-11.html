OpenAI–Cursor 大限就在明天（11 月 12 日）：但那是“提议日”，不是板上钉钉的断供日（11-10 跟进）

OpenAI 8 月 28 日宣布拟于 11 月 12 日终止向 Cursor 提供模型（SpaceX 收购 Anysphere 之后），但多家 11 月 10 日的跟进核查确认：11 月 12 日是 OpenAI 提议的日期，最新帮助文档称正式终止日待双方确定后另行通知，也可能提前；自带 API key 在 Cursor 里仍可继续用 OpenAI 模型；Cursor CEO 称 OpenAI 模型仅占其流量的约 5%。另有实测对比：Cursor 里最新的 OpenAI 模型仍停留在 GPT-5.6 家族（GPT-6/6.1 从未给过 Cursor），GPT-5.6 Sol 在 Terminal-Bench 4.0 上通过率 37.88%、单测成本 $7.98，而没给 Cursor 的 GPT-6.1 Sol 通过率 55.05%、单测仅 $1.72。对你：你不用 Cursor 主力开发，这条主要是行业风向——模型供应正在变成谈判筹码；但如果你偶尔用 Cursor，12 日前把默认模型切到 Claude/Gemini/Grok，别在截止日当天才发现 GPT 模型没了。

Claude Code 的批准流程正在泄露密钥：1,122 个公开仓库已中招（11-10，Outwire 安全简报）

Apiiro 确认：Claude Code 的“Yes, and don't ask again”批准流程会把完整明文命令（含嵌在里面的密钥）持久化写进项目 settings 文件，已导致 1,122 个公开 GitHub 仓库原样泄露密码与 API key；另有 Claude 文档处理工具的漏洞可被恶意临时文件利用、在用户 Linux 机器上执行任意代码。对你：这条必须马上动手——检查你所有用 Claude Code 的项目（kaoyan_chain、SmartVocab 等），确认 settings 文件里没有明文密钥、且没有把这类文件提交进公开仓库；昨天提醒过的“本地 MCP 配置别放明文密钥”同样适用，顺手把密钥都挪到环境变量或 Vault 里。
